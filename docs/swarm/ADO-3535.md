- fermo perché: The plan uses notice fields that the upstream xg JSON envelope does not have. The prompt says to report each notices[] entry verbatim 'using its received title, text, and url' and to deduplicate 'at most once per session per id'. I checked the upstream envelope in ADO-3537 (xrmghost-cli, commit 6f39d16091e2c5fded857efeed2e0bdbdd37af58). In Infrastructure/Notices/Notice.cs it is defined as `record Notice(string Kind, string Text, string? Url = null)`. CommandOutputEnvelope.ToJson writes only `kind`, `text` and optionally `url` for each notice. There is no `title` and no `id` field. The dependency that might add them, ADO-3594, is 'unknown' in the bundle and no task in this swarm realizes it. The envelope also has an optional top-level `error {type, message}`, which the prompt's constraint ('schema_version, command, result, exit_code, optional data, and notices') leaves out. Writing the skill as specified would tell agents to read and deduplicate on fields xg never emits. Choosing a different field for display and for the dedup key (for example kind, or text+url) would change the result, and that decision belongs to the planner. Needed: either fix the prompt to the real notice shape {kind, text, url?} with a stated dedup key, or make ADO-3594 (or a task in ADO-3537) add `id`/`title` to the envelope first. No files were changed.
